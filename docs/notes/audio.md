- **Provider platform**: `src/audio/` uses `BaseAudioProvider` ABC + `AudioProviderRegistry` + `AudioManager` chain pattern (same as publisher module)
- **Adding a provider**: create `src/audio/<provider>.py` with `@register_audio_provider` decorator, add enum value to `AudioProvider`, import in `__init__.py`, enable in YAML
- **Provider chain**: configured via `audio_providers` list in `video_production.yaml`. Tried in order; within a provider the candidates are ranked on the query's words and the first matching one that downloads wins; local files are last resort
- **Jamendo**: uses `client_id` auth only (no OAuth2), `fuzzytags` search for genre/mood matching, random query selection from configured pool
- **Jamendo CDN requires HTTP/2**: `prod-1.storage.jamendo.com` (behind Cloudflare/nginx) serves the actual MP3 only over HTTP/2; HTTP/1.1 requests get a blocking text/html page. aiohttp 3.x only supports HTTP/1.1, so `JamendoProvider.download()` uses `asyncio.create_subprocess_exec("curl", ...)` instead, which negotiates HTTP/2 by default. The search API (`api.jamendo.com`) works fine with HTTP/1.1 and still uses aiohttp. See `src/audio/jamendo_provider.py::JamendoProvider.download`.
- **Jamendo CDN is slow without proxy**: even with HTTP/2 via curl, the Jamendo CDN can be very slow in some network environments (~90 B/s, 3.3 MB tracks time out in 180s). Through a HTTP/SOCKS proxy, downloads typically complete in under 120s. The provider chain falls through to Freesound if Jamendo times out. If a run is missing background music, a proxy/VPN may be needed.
- **Freesound**: `FreesoundProvider` wraps existing `FreesoundClient` (don't modify the 728-line client directly). OAuth2 for full quality, API key for previews
- **Jamendo answers an identical query inconsistently.** Six repeats of one `fuzzytags=lofi` request returned `5 0 0 5 5 0`, and the pattern holds with and without `durationbetween`, `vocalinstrumental`, `audiodlformat` and `include`, so it is the service, not a parameter. The provider already retried an empty answer twice, drawing a fresh query each time (the emptiness is not query-specific, so re-drawing is as good as repeating), but three attempts at one-in-two odds are three coin flips: roughly one render in eight fell through to Freesound previews, which is what the 2026-09-19 batch log shows. Six attempts put a full run of misses near one in sixty for under two seconds of calls (#516). When the rate is measured again, the retry count is sized to it, not to a round number.
- **The test suite destroyed the real Freesound refresh token.** `test_oauth2_token_refresh_success` drove the real refresh path with a mocked response carrying the literal `new_refresh_token` and left `update_env_file` unpatched, so every suite run since 2026-01-12 wrote that literal into the repository's `.env`. Freesound rotates refresh tokens on use, so the real one cannot be recovered from any older copy; the remedy is `tools/freesound_oauth2_setup.py`, and the guard is a fixture that keeps every test away from the real file (#515). Proven by setting the key to a sentinel, running one file at a time, and reading it back; a test that persists a credential is a test that owns the path it persists to.
- **Config patterns**: Jamendo uses `audio_providers[].settings` dict, Freesound uses legacy `freesound_*` fields on `AudioSettings`. Both work, new providers should use the `settings` dict pattern
- **CircuitBreaker**: use public `record_success()`/`record_failure()` methods, not private `_on_success()`/`_on_failure()`
- **`silence_min_duration_sec` is a trim-MORE knob, not a trim-LESS knob**: the field in `AudioProcessingSettings` maps to ffmpeg `silenceremove` `start_duration`, which is the continuous non-silence window the filter must detect before it stops trimming. Audio during that window is **discarded**, not kept. So larger values trim MORE aggressively, and short trailing words (under ~0.4s, e.g. "tips", "tech") get eaten if `start_duration` exceeds the word length. Keep at 0.1s or below. Lives in `config/ai_services.yaml::audio_processing`.
- **A calm query returned a drill instrumental.** The Freesound search asked for rating order, which ranks the highest-rated sounds the text search loosely matched, and the chain accepted the first candidate that downloaded: "Battleground | UK Drill Instrumental" under a calm smartwatch pitch (2026-09-19). The search now honours `freesound_sort`, a setting that was shipped but never read (the client's own rating default applied), with relevance as its default, and asks for the sound's tags; Jamendo's tracks carry their `musicinfo` tags, and the manager ranks every provider's candidates by how many of the query's words their title or tags begin with, drops the ones that match none, and moves to the next provider when nothing matches; the audio summary names the matched terms. A word matches a tag it begins (`calm` matches `calming`), so compound tags count (#518).
- **The music step spent 208 s of a 304 s render on failures.** Two failed OAuth2 refreshes at ERROR for every candidate, although a token that failed once cannot become valid mid-run, then three one-minute timeouts downloading one preview before the next candidate was tried. The refresh is now attempted once per client and a failure is one WARNING with the remedy; a candidate is downloaded once within its timeout (the OAuth path's second attempt and the preview helper's three are gone); and `AudioManager` keeps the whole chain inside `music_search_budget_sec` (120 s, under the 180 s step warning), wrapping every search and download in the time left and using a local file when it is spent. `tests/audio/test_music_budget.py` stalls every download and shows the chain end inside the budget (#517).
- **A full download recorded no author or licence.** After an OAuth2 download the client fetched the sound's metadata and read the wrapper's `Sound` object with `.get`, which raised, so every full download's attribution was `Sound <id>`, author and licence `Unknown`: a Creative Commons compliance gap. It hid for eight months because the refresh token was dead and every render took the preview path, and the test mocked `get_sound` as a dict. `_field` reads a dict key or an attribute, the test mocks the real shape, and the setup tool says where the authorization code appears (Freesound's own `app authorized` page, not a localhost redirect) (#532).
- **The Freesound token settings were declared and never read.** `freesound_token_expiry_sec` and `freesound_token_refresh_buffer_sec` sat on the audio settings model and in the shipped yaml while the client used its own constants, and two nested retry blocks under them were not model fields at all, so the model dropped them silently (it ignores unknown keys). Nothing noticed because the defaults matched the constants. The provider now passes both flat settings to the client (a non-numeric value, as from a mocked config, falls back to the default), the fallback lifetime is Freesound's 24 hours, and the nested blocks are gone. `tests/audio/test_freesound_token_settings.py` changes both values on the loaded config and checks they reach the client, and a buffer test fails if the client goes back to a constant (#534).
- **Only a measured-silent TTS tag may reach the voice, and the documented list is not the measured one.** The captions are transcribed from the voiceover, so a tag the voice speaks becomes caption text. `tools/tts_tag_probe.py` voices one sentence pair per tag, transcribes it, and reports the gap between the sentences and any extra words. On `gemini-2.5-flash-tts` with Charon, three samples each: 0.5 s untagged, about 0.58 s `[short pause]`, 0.7 s `[medium pause]`, 1.0 s `[long pause]`, 0.9-1.1 s `[sigh]`, none transcribed. `[uhm]` came back as "Um," in one of four samples. The undocumented `[slow]` and `[fast]` also moved the gap (1.5-1.8 s and 0.35 s), and `[slow]` turned both full stops into exclamation marks, so an unmeasured tag is not inert. `SILENT_TTS_TAGS` is the accepted set, and a `pause_plan` refuses anything else at load. The stripper for fallback providers matched `[short pause]` and `[long pause]` but not `[medium pause]`, which a fallback voice would have read aloud; it now matches all three. In context the voice compresses the tags: `charon_varied`, with `[long pause]` at paragraph breaks, spread the gaps between sentences from 0.56-0.74 s to 0.42-0.82 s, so a medium pause alone is barely distinguishable from the voice's own gaps (#439).
